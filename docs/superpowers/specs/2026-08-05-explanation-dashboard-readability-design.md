# Explanation Dashboard Readability Design

## Goal

Make the V9 schema-3 explanation dashboard easier to scan and easier to trust by combining a narrative-first case readout with a compact, plain-language ranking comparison. Displayed numeric values must never exceed three decimal places.

This is a presentation-only change. Artifact schemas, evidence-boundary validation, lazy sidecar loading, graph construction, as-of semantics, and model/evaluation logic remain unchanged.

## Design direction

The page uses a calm evidence-reader hierarchy with an analyst-friendly ranking strip:

1. Case title, cohort/evidence status, and grounded narrative lead the selected-case view.
2. A three-column ranking strip immediately follows, showing Baseline, Seed-0 GNN, and Seed-0 Hybrid ranks with the Hybrid movement called out as a short sentence.
3. The strict as-of boundary remains visible as provenance, but moves to a quieter evidence note rather than competing with the headline.
4. Narrative, counterfactual factors, stability/faithfulness, attribution, and graph evidence remain available, but secondary numeric fields are visually subordinate.
5. The case list exposes the useful comparison at a glance: case identity, evidence status, and baseline-to-hybrid rank movement.

The graph remains an interactive, bounded presentation of the published as-of community. Graph controls, legend meaning, table fallback, and accessibility descriptions retain their current semantics.

## Visual system

- Canvas: near-black charcoal/zinc surfaces already used by the V9 dashboard.
- Typography: Outfit for headings and prose; JetBrains Mono for ranks, scores, IDs, timestamps, and tabular values.
- Accent: green for selected state, primary action, and validated evidence emphasis.
- Semantic colors: muted blue/amber/red may remain only where they encode caught state, evidence, warning, or failure; they are not decorative accents.
- Type scale: increase the explanation view's smallest prose labels to a readable 11px minimum where space permits; use 13px or larger for explanatory copy.
- Layout: use grid-first layout with clear zones, generous padding, and no overlapping content. Collapse the two-column evidence layout to one column below 900px and keep all controls at a 44px minimum touch target on narrow screens.
- Motion: retain restrained transitions only; respect `prefers-reduced-motion`. No new looping animation or glow effects.

## Numeric formatting contract

Add one JavaScript display formatter in `v9_recovery_explainer_ui.py`:

- finite numbers use `Intl.NumberFormat`/equivalent with `maximumFractionDigits: 3`;
- trailing zeroes are omitted (`0.842`, `0.5`, `1` rather than `0.842`, `0.500`, `1.000`);
- integer ranks/counts keep grouping where useful and do not gain decimal points;
- non-finite or missing values use the existing unavailable/placeholder copy;
- signed rank effects preserve an explicit `+` for positive values;
- JSON debug panels use a numeric replacer so nested values also obey the three-decimal limit;
- the formatter applies to visible text, table cells, tooltips/labels, and accessible descriptions generated by the recovery explorer.

Values in the artifact remain full precision. Only presentation strings are rounded.

## Component changes

### Case header and ranking strip

Refine the selected case header into a clear title/status area followed by a ranking strip. The strip uses three aligned cells for Baseline, Seed-0 GNN, and Seed-0 Hybrid. The Hybrid cell receives the strongest visual treatment, while the rank movement is expressed in both numeric and plain-language form (for example, “32 places higher than Baseline”).

Keep rank semantics explicit: these are anchor-event ranks, while cohort recovery remains unique-person recovery. Do not relabel the Hybrid percentile-fusion score as a probability.

### Narrative and evidence order

For technical explanations, render the grounded narrative before the detailed factors and graph. Keep measured counterfactual effects and attribution caveats adjacent to their values. The as-of boundary should remain a visible status/provenance block with readable wrapping rather than a dense single line.

### Case list

Keep the existing filter and selection behavior. Increase case-row spacing and make the baseline-to-hybrid movement a single visual badge/line instead of presenting several unexplained abbreviations. Preserve the underlying cohort and detail-status labels for accessibility and provenance.

### Secondary evidence

Keep stability, faithfulness, attribution, and complete data-table fallback. Improve headings and spacing, format every numeric cell consistently, and let the graph remain the visual anchor on wide screens. Do not remove evidence or change lazy-loading behavior.

## Testing and verification

- verify nested JSON panel formatting is capped at three decimals;
- verify the rendered V3 source contains the combined ranking strip, narrative-first order, and updated accessible labels;
- preserve existing schema validation, sidecar, focus, graph, and table-contract tests.

Run the focused recovery UI and dashboard-builder tests, compile the changed Python modules, rebuild the dashboard, and run `git diff --check`. Visually inspect the rebuilt desktop and narrow layouts through the existing headless browser workflow when available.

## Out of scope

- No changes to model training, scoring, artifact schemas, recovery selection, or evidence semantics.
- No changes to generated corpus data or recovery sidecars.
- No new reader/console mode toggle in this pass.
- No unrelated dashboard-tab redesign.
